02 — Day 0

Start with the mental model.

Today is not about memorizing syntax. It is about understanding what a query is asking the database to produce.

Today's objective

Read a table. Ask a precise question.

A SQL query is a specification for a result set. Start with the columns you need, identify the table that contains them, then add only the filters required by the question.

  • Know the difference between a database, table, row and column.
  • Write a basic SELECT ... FROM ....
  • Filter with WHERE.
  • Sort with ORDER BY.
  • Limit the result with LIMIT.
Worked example

Find the highest-value orders.

-- Start broad
SELECT *
FROM orders;

-- Choose only useful columns
SELECT order_id, customer_id, amount
FROM orders
ORDER BY amount DESC
LIMIT 5;

The database first identifies rows from orders, then returns the requested columns, sorts the result by amount from high to low, and keeps the first five rows.

04 — Best practices

How to become good at SQL.

Syntax is the easy part. The durable skill is translating a question into a correct, testable result.

01

Think in result sets

Before writing SQL, state exactly what one output row represents. This prevents many join and aggregation errors.

  • Define the grain.
  • Choose required columns.
  • Then choose joins and filters.
02

Build in layers

Do not write a 50-line query in one shot. Start with the base rows, inspect them, then add one transformation at a time.

  • Base query.
  • Filter.
  • Join.
  • Aggregate or window.
03

Validate aggressively

A query that runs is not necessarily correct. Check row counts, duplicates, NULLs, edge cases and totals.

  • Test small samples.
  • Compare totals.
  • Check boundary dates.

The fastest route to advanced SQL is not more syntax. It is more deliberate practice on increasingly difficult questions.
